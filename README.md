# 다시담기

쿠팡 상품 링크를 등록하고, 선택한 옵션으로 장바구니에 담으며 구매 주기를 관리하는 개인용 Android 앱입니다. 현재 버전은 **0.10.0**입니다. 상품·옵션·구매 이력은 기기에 저장하며 별도 서버나 쿠팡 API를 사용하지 않습니다. **실제 결제와 자동 구매 예약은 차단되어 있습니다.**

## 링크로 상품 등록

1. **상품 등록**에서 선택한 옵션의 쿠팡 상품/공유 링크를 입력합니다.
2. **링크에서 상품 불러오기**를 누릅니다. 쿠팡 앱을 열어 상품명·현재 옵션을 읽고 다시담기로 돌아옵니다. Android 접근성의 **다시담기 구매 도우미**가 켜져 있어야 합니다.
3. 읽은 상품과 옵션을 확인하고 **상품 정보 적용**을 누릅니다. 상품명·옵션을 다시 타이핑할 필요가 없습니다.
4. 구매 수량·주기·다음 구매일을 확인하고 **저장**합니다. 기본값은 수량 1개, 30일, 오늘이며 직접 바꿀 수 있습니다. 결제 전 확인 한도는 카드 저장 시 생략할 수 있습니다.

링크는 필수입니다. 링크를 바꾸면 이전 상품명·옵션은 비워 잘못 조합해 저장하지 않도록 합니다. 읽지 못한 정보는 **상품 정보 직접 보완**에서 직접 또는 이미지로 보완할 수 있습니다. PC 이미지가 들어오면 보완 영역이 자동으로 열리며 기존 양식은 유지됩니다. 이미지에 URL이 없으면 링크를 따로 넣어야 합니다.

공개 상품 페이지 요청은 샘플에서 HTTP 403으로 거부되어, 상품 정보는 사용자의 쿠팡 앱 상세 화면에서 읽습니다. 읽은 값은 검토용이며 화면에 없는 정보나 식별 번호를 추측하지 않습니다. 정보 읽기는 상품을 담거나 주문하지 않습니다. 재생성·프로세스 재시작만으로 읽기를 자동 재실행하지 않습니다.

## 카드에서 옵션 선택

카드의 **옵션 링크 추가**로 같은 상품의 다른 옵션 링크를 등록합니다. 추가한 옵션은 **옵션 선택**에서 고릅니다. 선택하면 상품명·옵션·해당 상품 주소를 함께 저장하며 다음 단일·묶음 담기에 그대로 사용합니다. 수량·주기·날짜·한도는 유지합니다.

URL 하나에서 전체 판매 옵션을 자동 수집하는 기능은 아닙니다. 현재 링크가 가리키는 옵션을 읽고 실제로 확보한 다른 옵션 링크를 추가하는 방식입니다. 같은 상품의 옵션을 최대 20개 저장하며 다른 상품 링크·중복 주소는 거부합니다. 상품명·주소·옵션을 직접 바꾸면 어긋나는 기존 옵션 목록을 초기화합니다.

## 장바구니 담기

카드의 기본 **장바구니 담기** 버튼으로 한 상품을, 목록 위의 **모두 장바구니에 담기**로 활성 상품들을 순서대로 담습니다. 등록한 상품·옵션의 요약을 확인하고 명시적으로 시작합니다. 기존의 담기 실험 메뉴와 별도 담기 전 점검 버튼은 제거했습니다.

- 현재 구매 수량 1개를 지원합니다. 묶음은 일시정지·보관 상품을 제외하고 최대 20개이며 다음 구매일과 관계없이 표시된 활성 상품 전체가 대상입니다.
- 쿠팡 상세 화면의 상품명·옵션·버튼 구조가 일치할 때 담기 버튼을 한 번 누릅니다. 이미 담긴 상품은 기존 수량이 증가할 수 있으므로 실제 수량은 쿠팡에서 확인해야 합니다.
- 묶음은 모든 상품 주소를 먼저 확인하고, 앞 상품의 담기 완료 안내를 확인한 뒤에만 다음 상품을 시작합니다. 실패·중단·결과 불명 시 나머지는 실행하지 않습니다.
- 중복 시작·같은 묶음 안의 중복 상품·중단 후 자동 재실행을 막습니다. 사용자가 종료 후 다시 시작하면 별도의 담기 실행입니다.
- 금액 한도를 확인하거나 주문·결제·구매 완료를 실행하지 않습니다. 지정 시각의 자동 담기와 자동 주문서 이동은 아직 제공하지 않습니다.

실행 결과는 앱으로 돌아와 확인합니다. 필요한 경우 **상세 실행 기록**을 펼칠 수 있습니다. 상품명·옵션 대조, 클릭 선점, 완료 안내 확인과 중복 방지는 정식 기능의 내부 검증으로 유지합니다.

## 구매 완료와 알림

쿠팡에서 주문을 확인한 뒤 카드의 **구매 완료 기록**을 누르고 확인합니다. 실제 결제 여부는 사용자가 판단하며 앱은 주문 결과를 조회하지 않습니다. 같은 회차를 여러 번 눌러도 이력과 일정은 한 번만 갱신합니다. 상품을 보관해도 과거 이력은 유지합니다.

다음 구매일은 **실제 완료한 기기 현지 날짜 + 구매 주기**입니다. 알림은 설정한 시각을 기준으로 WorkManager가 예약합니다. 절전·기기 상태에 따라 늦을 수 있으며 정확한 시각을 보장하지 않습니다. 일시정지·수정·보관 시 오래된 알림은 만료됩니다.

## 남겨 둔 결제 전 시험

카드의 관리 메뉴 **⋯ → 결제 전 시험**, 또는 **설정 → 결제 전 시험 설정**에서 엽니다. 등록 조건과 배송비 포함 한도를 확인하고 직접 시작해야 합니다. 상품 화면의 **바로구매**로 주문 화면을 확인하는 시험이며 최종 **결제하기**는 누르지 않습니다.

현재 결제 화면의 상품 행·수량·최종 금액 검증은 완성되지 않았습니다. 읽을 수 있는 단계까지만 확인하고 중단할 수 있습니다. 로그인·비밀번호·본인 인증·보안문자는 조작하지 않으며 실제 결제·자동 구매·자동 예약은 활성화할 수 없습니다. 시험으로 구매 이력이나 다음 구매일을 바꾸지 않습니다.

## PC 이미지와 클립보드

Windows에서 캡처한 상품 이미지는 `tools`의 콘솔 전송기로 BlueStacks에 보낼 수 있습니다.

```powershell
dotnet publish .\tools
.\tools\dist\RebuyClipboard.exe send --clipboard
.\tools\dist\RebuyClipboard.exe send --image 'C:\captures\product.png'
.\tools\dist\RebuyClipboard.exe sample show
```

Windows용 EXE는 .NET Windows Desktop Runtime 10과 ADB가 필요합니다. 기본 기기는 `127.0.0.1:5555`이며 `--device`·`--adb`로 바꿀 수 있습니다. 요청할 때만 클립보드를 읽으며 자동 감시나 자동 담기는 하지 않습니다. 자세한 명령은 [tools/README.md](tools/README.md), 공통 상품 링크는 [testdata/README.md](testdata/README.md)에 있습니다.

Android 클립보드 이미지와 사진 선택도 **상품 정보 직접 보완**에서 사용할 수 있습니다. 인식 결과를 확인하고 적용해야 양식이 바뀝니다. 한국어 ML Kit 모델을 APK에 포함해 기기에서 읽으며 자체 서버에 이미지를 보내지 않습니다. ML Kit는 성능·사용 통계를 Google에 전송할 수 있습니다. [개인정보 안내](https://developers.google.com/ml-kit/terms)를 참고하세요. PC 전송 이미지는 검토 종료 후 앱 전용 임시 저장소에서 삭제합니다.

## 빌드와 설치

Android 8.0(API 26) 이상을 지원합니다. Android Studio에서 저장소를 열고 JDK 17, Android SDK Platform 35와 Build Tools 35.0.0을 준비합니다. `local.properties`의 `sdk.dir` 또는 `ANDROID_HOME`에 실제 SDK 경로를 지정합니다. 컴퓨터별 설정·SDK·빌드 출력은 Git에 포함하지 않습니다.

```powershell
.\gradlew.bat :app:assembleDebug
adb -s 127.0.0.1:5555 install -r .\app\build\outputs\apk\debug\app-debug.apk
```

디버그 APK는 `app/build/outputs/apk/debug/app-debug.apk`에 생성됩니다. 개발용 서명을 사용합니다. 기존 데이터는 Room v1→v2→v3으로 이전하며 앱을 삭제하면 로컬 데이터도 삭제됩니다.

구성: Kotlin 2.1.20, Jetpack Compose, Room 2.7.1, WorkManager 2.10.1, DataStore 1.1.4. Gradle Wrapper 8.11.1과 Android Gradle Plugin 8.9.2를 사용합니다.

개발 검사는 `app/src/test`와 `app/src/androidTest`에 유지하며 앱의 시험 메뉴와 구분합니다. 접근성 도우미가 실제 동작하는 동안 instrumentation이나 `uiautomator dump`를 실행하면 서비스가 끊길 수 있으므로 실제 연동 확인에는 화면 캡처와 완료 상태를 사용합니다. 실제 확인 범위와 과거 결과는 [VALIDATION.md](VALIDATION.md)에 기록합니다.
