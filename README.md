# 다시담기 — 쿠팡 정기 구매 관리 MVP

개인용 Android 앱입니다. 상품을 등록하고 구매 예정일에 알림을 받은 다음, 쿠팡에서 직접 주문하고 앱에서 구매 완료를 기록합니다. 계정·서버·쿠팡 API·자동 결제는 사용하지 않습니다. 0.7.0-preview에는 Windows에서 캡처한 이미지를 블루스택의 상품 입력 화면으로 보내는 PC 전송기를 추가했습니다. 상품 등록·수정에서 옵션과 금액 한도까지 한 번에 저장합니다. **사용자의 구매 금지 지시에 따라 실제 결제와 자동 구매 예약은 코드에서 차단되어 있습니다.**

0.7.7-preview의 장바구니 테스트는 **쿠팡 앱의 상품 화면으로만** 연결합니다. 공유 링크는 화면에 보이는 WebView에서 공개 이동 주소를 확인한 뒤 쿠팡 앱으로 전달합니다. 주소를 확인하지 못하거나 앱을 열 수 없으면 사유를 표시하고 멈춥니다. 일반 **쿠팡 열기**에는 브라우저 연결이 가능하지만, 장바구니 도우미는 브라우저에서 담기를 시도하지 않습니다.

이미지 인식은 브랜드 이동 문구·원산지·판매 안내를 상품명에서 제외하고, 상품 상세 문맥과 구성 정보를 이용해 전체 상품명을 먼저 제안합니다. `개당 중량 × 수량 285gx1세트`처럼 붙은 표기와 분리된 OCR 조각도 실제 읽힌 단위·수량으로 결합합니다. 작은 스크린샷은 크기·메모리 한도 내에서 확대하고, 좌표상 가까운 같은 행의 명확한 중량·수량 표시만 합칩니다. 단위나 숫자를 추측해 보충하지 않습니다.

장바구니 입력 창을 연 상태에서 PC 전송기로 이미지를 보내면 해당 창에서 인식 결과를 검토합니다. 기존 URL과 입력값을 유지하고, **입력란에 적용**을 눌러야 상품명·옵션이 바뀝니다. 이미지 전송이나 적용만으로 담기가 시작되지는 않습니다.

장바구니 시험 창의 **담기 전 점검**은 상품명·선택 옵션·상세 화면의 담기 버튼이 일치하는지만 확인합니다. 실제 담기 버튼은 누르지 않으며 결과에도 추가하지 않았음을 표시합니다. 실제 추가는 별도의 **1개 추가 시작**으로 실행합니다. `개당 중량 × 수량 285g × 1세트` 같은 화면의 옵션 항목명은 포장 옵션과 구분해 비교하고, 수량·단위가 다르면 중단합니다. 막힌 단계는 앱으로 돌아와 결과에서 확인할 수 있습니다.

0.7.6은 접근성 트리에서 구조용 레이아웃도 받도록 설정했습니다. 0.7.5의 실제 실행에서 담기 버튼이 보여도 상세 화면 구조 확인이 실패한 지점에 대한 보완이며, 0.7.6의 실제 담기 성공은 아직 확인하지 못했습니다. 상품명·옵션·버튼의 일치 조건과 한 번만 담기 제한은 유지합니다. 개발 중 실제 도우미가 실행되는 동안 `uiautomator dump`나 instrumentation을 사용하면 접근성 서비스가 중단될 수 있습니다. 실행 중 검증은 화면 캡처만 사용하고, 종료 후 앱 결과를 확인하세요.

0.7.7의 **마지막 실행 진단 보기**에서는 실행 단계, 상품명·옵션·담기 버튼 확인 여부, 화면 구조별 확인 결과와 읽은 노드 수를 확인합니다. 제한 시간 초과 전의 마지막 단계와 접근성 서비스 중단·연결 해제·사용자 중지를 구분하며, 클릭 요청 선점과 Android의 클릭 수락도 구분합니다. 마지막 진단은 앱을 다시 열어도 남습니다. **진단 내용 복사**를 누르면 그 진단만 복사합니다. 화면 원문·상품명·URL·계정 정보는 진단에 저장하지 않으며, 진단 조회만으로 담기가 시작되지는 않습니다.

## PC 캡처를 블루스택으로 보내기

PC 도구 소스는 `tools`에 있습니다. GUI 전송기를 콘솔 CLI 1.1.0으로 바꿨습니다. 저장소 루트에서 게시 프로필로 EXE를 만든 뒤 실행합니다.

```powershell
dotnet publish .\tools
.\tools\dist\RebuyClipboard.exe --help
.\tools\dist\RebuyClipboard.exe devices

# Win+Shift+S로 상품을 캡처한 뒤 실행
.\tools\dist\RebuyClipboard.exe send --clipboard

# 저장된 이미지를 확인하거나 보내기
.\tools\dist\RebuyClipboard.exe check --image 'C:\captures\product.png'
.\tools\dist\RebuyClipboard.exe send --image 'C:\captures\product.png'
```

블루스택을 실행하고 최신 다시담기 APK를 설치해야 합니다. 기본 배포는 EXE 하나이며 .NET Windows Desktop Runtime 10과 별도의 ADB가 필요합니다. 기본 기기는 `127.0.0.1:5555`, ADB는 `C:\platform-tools\adb.exe` 등을 자동 탐색합니다. `--adb`와 `--device`로 바꿀 수 있습니다. 인자 없이 실행하면 도움말을 표시합니다.

전송 후 Android 앱에서 인식 결과를 검토하고 **입력란에 적용**을 누릅니다. 기존 상품 등록·수정 창이 열려 있으면 작성하던 입력을 유지합니다. 가격은 자동 선택하지 않고 이미지에 없는 URL·구매 수량·주기·날짜를 추측하지 않습니다. 전송만으로 상품 저장·장바구니·주문이 실행되지 않습니다.

`send --clipboard`를 실행할 때만 Windows 클립보드의 이미지를 읽습니다. 자동 감시·클립보드 변경·화면 자동 캡처는 없습니다. PNG를 로컬 ADB로 전달하며 자체 서버를 사용하지 않습니다. 종료 코드는 `$LASTEXITCODE`로 확인합니다. 자세한 명령·빌드 방법은 [tools/README.md](tools/README.md)에 있습니다.

전송본은 Android 앱 전용 캐시에만 잠시 보관하고 **적용·취소·읽기 중단** 때 삭제합니다. 검토를 끝내지 않고 앱을 닫으면 다음 이미지 처리 때 10분이 지난 임시 파일을 정리합니다. 일반 Android 앱은 전송함에 접근할 수 없으며 ADB shell과 다시담기 자신의 UID만 사용합니다. 입력은 PNG 24MB 이하로 제한합니다.

## 클립보드 이미지 붙여넣기 (0.6.0-preview)

1. Android에서 상품 이미지 한 장을 복사합니다. 상품 주소나 이미지 URL을 텍스트로 복사한 것은 해당하지 않습니다.
2. **상품 등록·수정** 또는 **장바구니 담기 실험**에서 **클립보드 이미지 붙여넣기**를 누릅니다.
3. 사진 선택과 같은 검토 화면에서 상품명·옵션·금액 후보를 확인한 뒤 **입력란에 적용**을 누릅니다. 가격은 기본적으로 선택되지 않습니다.

버튼을 누를 때만 클립보드를 읽으며 자동 감시·수정·삭제는 하지 않습니다. 이미지가 없거나 여러 장이거나 접근 권한이 만료되면 기존 양식의 입력을 유지하고 안내합니다. 이미지를 다시 복사하거나 기존 **상품 이미지에서 읽기**로 사진을 선택할 수 있습니다. 이 기능은 저장·장바구니 추가·주문을 자동 실행하지 않습니다.

이 버튼은 **Android 클립보드의 이미지 URI**를 읽습니다. Windows에서 캡처한 이미지는 위의 PC 전송기를 사용하세요. Android의 이미지 복사·붙여넣기는 [공식 클립보드 문서](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste)의 content URI 방식을 사용합니다.

## 상품과 구매 조건 한 번에 저장하기 (0.5.0-preview)

**상품 등록** 또는 **상품 수정**에서 상품명, 쿠팡 URL, 구매 옵션, 배송비 포함 금액 한도, 수량, 주기, 다음 구매일을 입력하고 **저장**을 누릅니다. 옵션과 한도는 필수이며 한도는 1원~1억원입니다. 옵션의 `600ml, 2개`는 한 상품의 포장 구성이고, 구매 수량은 그 구성을 몇 개 주문할지 정하는 별도 값입니다.

0.7.1-preview부터 상품 카드의 **장바구니 담기 실험**에도 등록한 옵션을 자동으로 채웁니다. 예를 들어 `285g × 1세트`로 저장했다면 시험 창에 같은 값이 표시됩니다. 시험 창에서 임시로 수정한 값은 등록 정보에 저장되지 않으며 다시 열면 등록한 옵션을 불러옵니다. 옵션이 없는 예전 상품이나 설정에서 연 시험 창은 직접 입력할 수 있습니다.

이미지에서 읽은 상품명·옵션·선택한 금액도 이 양식에 함께 반영됩니다. 저장은 상품과 구매 조건을 같은 Room 행에 원자적으로 기록합니다. 입력 검증이나 DB 쓰기에 실패하면 일부 항목만 저장되지 않습니다. 저장만으로 쿠팡을 열거나 시험·장바구니·주문을 시작하지 않습니다.

**구매 조건 · 결제 전 시험**에서는 이미 등록한 조건을 그대로 확인합니다. 수정이 필요하면 **상품·구매 조건 수정**으로 같은 상품의 등록 양식을 열어 고칩니다. 별도로 같은 값을 다시 저장할 필요가 없습니다. 기존 버전의 상품과 이력은 DB v1→v2 마이그레이션으로 유지합니다. 과거에 별도로 저장한 구매 조건은 URL·수량이 일치하는 상품의 수정 화면에서 불러오며, 확인 후 한 번 저장하면 통합됩니다.

## 상품 이미지로 입력하기 (0.4.0-preview)

1. **상품 등록·수정** 또는 **장바구니 담기 실험**의 **상품 이미지에서 읽기**를 누릅니다.
2. Android 사진 선택기에서 상품명·옵션·가격이 보이는 이미지나 스크린샷 한 장을 고릅니다. 사진 전체 접근이나 카메라 권한은 요구하지 않습니다.
3. 인식 결과에서 상품명과 옵션을 검토하고 수정합니다. 다른 후보가 있으면 **후보**에서 고를 수 있습니다. 쿠팡의 여러 추천 상품이 함께 보이는 사진에서는 원하는 상품의 정보인지 확인해 주세요.
4. 상품 등록·수정에서는 표시가격 후보를 직접 고를 수 있습니다. 기본값은 **가격 적용 안 함**이며, 할인 전·후 가격이 있으면 둘 다 제시합니다. 원 표시가 인식되지 않은 독립된 쉼표 숫자는 **금액인지 확인이 필요한 숫자**로 분리합니다. 이런 숫자는 가격이라고 확정하지 않으며, 사용자가 확인하고 원 단위로 사용하기를 선택해야 합니다. 선택한 값은 한도 입력란에 복사되므로 배송비 포함 최종 한도로 다시 확인해 주세요.
5. **입력란에 적용**을 눌러 기존 양식에 채웁니다. 이 버튼은 상품 저장·시험 시작·장바구니 추가·주문을 실행하지 않습니다. 읽지 못한 항목은 기존 입력값을 유지합니다.

상품 등록·수정은 상품명·옵션·선택한 금액과 보이는 URL을, 장바구니 시험은 상품명·옵션·보이는 URL을 반영합니다. 이미지에 URL이 없으면 주소나 상품 ID를 추측하지 않습니다. **쿠팡 공유 링크는 별도로 붙여 넣어 주세요.** 포장 옵션의 `2개`는 주문 수량 2개로 바꾸지 않습니다. 주기와 다음 구매일도 변경하지 않습니다.

한국어 ML Kit 모델을 APK에 포함해 기기에서 인식합니다. 사진 선택기의 원본과 원시 인식 텍스트를 별도로 저장하거나 자체 서버로 보내지 않습니다. PC 전송 이미지는 위에서 설명한 임시 캐시를 사용합니다. 사용자가 양식에서 저장한 상품 정보는 로컬에 남습니다. ML Kit는 성능·사용 통계를 Google에 전송할 수 있습니다. [ML Kit 개인정보 안내](https://developers.google.com/ml-kit/terms)를 참고하세요. 인식이 틀릴 수 있으므로 저장 전에 확인해 주세요. 이미지 입력은 24MB 이하이며, 메모리 사용을 위해 긴 변을 최대 3,072px로 축소합니다. 긴 스크롤 캡처의 작은 글자는 상품 부분을 잘라 다시 선택하면 더 잘 읽힐 수 있습니다.

동봉된 `examples/product-ocr-sample.png`는 검증용으로 만든 합성 이미지입니다. 쿠팡 화면이나 현재 판매가를 제공하는 자료가 아닙니다.

## 결제 전 시험

1. 구매 목록에 상품을 등록합니다. 쿠팡 공유 URL도 사용할 수 있습니다. 현재 시험은 구매 수량 1개만 지원합니다.
2. 상품 카드의 **구매 조건 · 결제 전 시험** 또는 설정의 **결제 전 시험 설정**을 엽니다.
3. 등록 화면에서 함께 저장한 상품명·옵션·금액 한도를 확인합니다. 조건이 없는 기존 상품은 **상품·구매 조건 수정**에서 입력하거나 이전 조건을 확인해 저장합니다.
4. Android 설정 → 접근성 → **다시담기 구매 도우미**를 직접 켜고 앱으로 돌아옵니다. 권한을 켜도 시험은 자동으로 시작되지 않습니다.
5. **결제 전까지 시험**을 누릅니다. 도우미는 공개 상품 링크로 쿠팡 앱을 열고 상품명·옵션이 일치할 때만 **바로구매**로 주문 화면을 엽니다. 최종 **결제하기**는 누르지 않습니다.

현재 쿠팡 9.4.5 결제 화면의 상품 행·수량을 안정적으로 검증하는 선택자는 확보하지 못했습니다. 할인 전·후 가격이 함께 표시되면 정확한 총액을 구분하지 않습니다. 따라서 해당 화면에 도달해도 조건 검증 실패로 중단할 수 있으며, 실제 주문 성공이나 완전 무인 구매를 지원한다고 표시하지 않습니다. 로그인·비밀번호·본인 인증·보안문자는 조작하지 않습니다.

상품과 구매 조건의 원본은 Room에 함께 저장합니다. 직접 시험을 시작할 때만 현재 조건의 스냅샷과 새 버전 ID를 DataStore에 기록합니다. 예전 옵션·한도 스냅샷으로 새 조건의 시험을 시작할 수 없습니다. 같은 회차의 실행을 원자적으로 선점하고, 프로세스가 중단된 실행은 자동 재실행하지 않습니다. 실제 실행 요청, 자동 구매 활성화, 결제 전송 승인은 모두 거절합니다. 자동 구매 예약기는 기존 작업을 취소하고 새 작업을 등록하지 않으며, 오래된 작업이 실행되어도 쿠팡을 열지 않습니다. 시험으로 구매 이력이나 다음 구매일을 변경하지 않습니다.

## 빠른 실행

Android 8.0(API 26) 이상에서 사용할 수 있습니다. 제공된 `rebuy-debug.apk`를 휴대폰으로 옮겨 설치하거나 Android Studio에서 프로젝트 폴더를 엽니다. 개발용 APK이므로 배포 서명은 포함하지 않습니다.

1. 앱의 **상품 등록**에서 상품명과 쿠팡 상품 또는 공유 HTTPS URL을 입력합니다.
2. 구매 옵션과 배송비 포함 금액 한도, 수량, 구매 주기(일), 다음 구매일을 정하고 저장합니다. 상품명은 쿠팡 표시 그대로 입력하거나 이미지에서 읽어 확인합니다. 쿠팡 서버에서 가격·재고·상품 정보를 조회하지 않습니다.
3. 알림을 허용하고 **설정**에서 알림 시간을 지정합니다. 기본값은 기기 현지 시간 오전 9시입니다.
4. 예정일 알림 본문 또는 **쿠팡 열기**를 눌러 쿠팡 앱이나 브라우저에서 직접 구매합니다. 수량을 쿠팡에 자동 반영하지 않으므로 등록한 수량을 확인해 주세요.
5. 알림의 **구매 완료 확인** 또는 앱 목록의 구매 완료 버튼에서 **구매 완료 기록**을 누릅니다. 실제 결제 여부는 사용자가 확인합니다.
6. **구매 이력**에서 기록을 확인합니다. 상품은 일시정지·수정·보관할 수 있고, 보관해도 기존 구매 이력은 남습니다.

**다음 구매일 규칙:** 실제 완료한 기기 현지 날짜 + 등록한 주기입니다. 예를 들어 10월 21일에 7일 주기의 구매를 완료하면 다음 구매일은 10월 28일입니다. 일찍 구매하거나 예정일을 지나 구매해도 완료일을 기준으로 계산합니다. 최초 입력 날짜는 2000~2100년 범위이고 자동 주기 계산은 경계에서 잘라내지 않습니다.

## 테스트

`testDebugUnitTest`는 순수 Kotlin 테스트와 Robolectric에서 실제 Room SQLite를 이용하는 테스트입니다. 동시 구매 완료 요청, 중복 재실행, 변경된 알림 거부, 이력 스냅샷, 시간대·자정 경계, URL 검증, 예약 시간 계산과 알림 동작을 검증합니다. `lintDebug`는 Android 정적 분석입니다.

실기기 또는 에뮬레이터에서 실행하는 테스트도 포함합니다. BlueStacks에서 기존 앱을 유지하며 검사하려면:

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb shell am instrument -w -r dev.local.rebuy.test/androidx.test.runner.AndroidJUnitRunner
```

`am instrument`는 시작·종료 때 대상 앱을 강제 종료합니다. 이 BlueStacks 환경에서는 접근성 서비스도 끊기는 것을 확인했습니다. 장바구니 도우미가 켜진 상태의 실제 화면 점검에는 위 명령을 사용하지 말고 일반 앱의 **담기 전 점검**을 사용하세요. 자동 검사 뒤에는 앱을 일반 실행하고 연결 상태를 확인해야 합니다. 앱 업데이트는 기존 상품 데이터를 유지하지만 서비스의 재연결 시간이 필요할 수 있습니다.

기기 테스트는 Room 트랜잭션과 Compose의 상품 등록 → 구매 완료 → 이력 저장 흐름을 검증합니다. 알림 허용 팝업이 흐름을 방해한다면 앱 권한을 먼저 설정해 주세요. 제공된 `VALIDATION.md`에는 실제로 수행한 검사와 실행하지 못한 검사를 구분해 두었습니다. GitHub Actions 설정은 단위 테스트·Lint·앱 APK 및 기기 테스트 APK 빌드를 수행합니다.

추가로 기기에서 확인할 항목:

- 오늘 날짜와 몇 분 뒤의 알림 시간으로 상품을 등록해 알림 본문이 상품 URL을 여는지 확인합니다.
- **구매 완료 확인**을 눌렀을 때 앱이 최종 확인을 요구하고, 연속 클릭·오래된 알림으로 이력이 늘어나지 않는지 확인합니다.
- 알림 거부 → 허용, 상품 일시정지·보관, 알림 시간 변경 후 취소·재예약을 확인합니다.
- 재부팅, 기기 시간·시간대 변경, 절전 상태에서의 알림 지연을 확인합니다.

## 구조와 중복 방지

```text
Compose / MainActivity
    └─ RoutineViewModel
        ├─ RoutineRepository ── Room(AppDatabase)
        ├─ SettingsRepository ── Preferences DataStore
        └─ ReminderScheduler ── WorkManager
              ├─ ReminderWorker ── Android 알림
              └─ ReconcileWorker ── 예약 복구·정리
```

- `ui/`: 구매 목록, 등록·수정, 완료 확인, 이력, 설정과 상태 처리.
- `domain/`: HTTPS 쿠팡 URL 검증, 날짜 계산, 완료 처리 결과.
- `data/`: 상품·옵션·금액 한도와 구매 이력, DAO, Room 트랜잭션. 데이터베이스 버전 1·2의 스키마를 `app/schemas/`에 저장하며 v1→v2 마이그레이션을 제공합니다. 파괴적 마이그레이션은 활성화하지 않습니다.
- `settings/`: 알림 활성화와 시각을 DataStore에 저장합니다.
- `reminders/`: 상품별 고유 Work, 알림 전달 기록, 재부팅·시간대 변경 시 재예약, 외부 URL 열기.

상품의 한 구매 회차마다 UUID `cycleId`가 있습니다. 완료 요청은 화면이나 알림이 받은 회차 ID를 그대로 전달합니다. Room 트랜잭션 안에서 현재 회차인지 검사하고, 구매 이력의 `(itemId, cycleId)` 고유 인덱스로 두 번째 쓰기를 막은 뒤 이력 추가와 다음 날짜·회차 갱신을 함께 커밋합니다. 수정·일시정지·보관은 회차를 바꾸므로 오래된 알림은 현재 회차를 완료할 수 없습니다. 상품명·URL·수량·예정일은 이력에 스냅샷으로 보관합니다.

알림은 상품별 고유 작업 이름과 회차·시간 설정 서명을 사용합니다. 같은 설정을 반복 동기화해도 기존 예약을 미루지 않으며, 회차별 전달 기록을 DataStore에 저장해 반복 알림을 막습니다. 알림 ID는 상품별 태그로 구분하고 PendingIntent는 상품·회차별 URI와 불변 플래그를 사용합니다. 알림 게시와 전달 기록 저장 사이에서 프로세스가 종료되면 동일 알림이 다시 게시될 수 있지만 기존 태그를 덮어씁니다. 구매 이력의 중복 방지는 별도 Room 트랜잭션이 보장합니다.

## 알림·개인정보 특성

WorkManager는 정확한 시각을 보장하는 알람이 아닙니다. 절전·배터리 최적화·제조사 정책 때문에 늦어질 수 있습니다. 앱 시작·복귀, 재부팅, 시간·시간대 변경, 12시간 간격 점검 시 예약을 복구합니다. Android의 앱 **강제 종료** 뒤에는 다시 앱을 열어야 백그라운드 작업이 재개될 수 있습니다. 알림을 닫으면 같은 회차의 알림을 반복 발송하지 않으므로 미완료 구매는 앱 목록에서 확인합니다.

앱은 쿠팡 공유 주소의 일반 HTTPS 리디렉션을 확인하기 위해 인터넷 권한을 사용합니다. 상품 주소는 쿠팡 도메인으로 제한하고 로그인 쿠키나 자격 증명을 사용하지 않습니다. 상품·이력·설정은 앱 전용 로컬 저장소에 남습니다. 자체 서버·계정 동기화는 없습니다. OCR에는 Google ML Kit가 포함되며 이미지·인식 결과는 기기에서 처리하고 SDK 성능·사용 통계는 전송될 수 있습니다. Android 백업과 기기 전송 규칙에서 데이터 제외를 설정했습니다. 수동 백업·내보내기·구매 취소 수정·자동 결제는 이 MVP에 포함하지 않습니다.

## 장바구니 접근성 실험 (0.2.0)

상품 카드 또는 설정의 **장바구니 담기 실험**에서 실행합니다. Android 접근성 설정에서 **다시담기 구매 도우미**를 사용자가 직접 켜야 합니다. URL, 쿠팡에 표시되는 정확한 상품명과 옵션을 입력한 뒤 **1개 추가 시작**을 누릅니다. 상품명과 옵션을 확인할 수 없거나 화면 구조가 다르면 멈춥니다. 한 번 시작할 때 장바구니 수량 1개만 추가하며 기존에 같은 상품이 있으면 수량이 증가할 수 있습니다. 구매 이력과 다음 구매일은 자동 변경하지 않습니다.

이 기능은 쿠팡 9.4.5의 관찰된 공개 상품 링크와 화면 구조를 대상으로 한 실험입니다. 공식 SDK가 아니므로 앱 업데이트·로그인 상태·옵션 선택 화면에 따라 실패할 수 있습니다. 접근성 권한을 활성화한 실제 앱의 담기 실행은 아직 검증하지 않았습니다. 에뮬레이터를 외부에서 조작해 장바구니에 담은 결과는 이 서비스의 성공 증거가 아닙니다. 결과가 불확실하면 장바구니를 확인한 뒤 재실행해야 합니다. 실행 상태를 저장하고 한 세션에서 담기 버튼을 한 번만 누르며, 프로세스 재시작 뒤 자동으로 재실행하지 않습니다.

사용자가 최종적으로 요청한 **정기 무인 주문·결제**는 현재 구현에 포함하지 않았습니다. 쿠팡의 공개 Open API는 판매자 운영용이며, 확인한 공개 목록에서 구매자 주문 생성·결제 API는 찾지 못했습니다. 장바구니 실험과 정기 자동 구매를 같은 기능으로 표시하지 않습니다.
