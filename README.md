# 다시담기

쿠팡 상품 링크를 등록하고, 선택한 옵션으로 장바구니에 담으며 구매 주기를 관리하는 개인용 Android 앱입니다. 현재 버전은 **0.14.4**입니다. 상품·옵션·구매 로그는 기기에 저장하며 별도 서버나 쿠팡 API를 사용하지 않습니다. **실제 결제와 자동 구매 예약은 차단되어 있습니다.**

## 링크로 상품 등록

1. **상품 등록**에서 선택한 옵션의 쿠팡 상품/공유 링크를 입력합니다.
2. **링크에서 상품 불러오기**를 누릅니다. 쿠팡 앱을 열어 상품명·현재 옵션을 읽고 다시담기로 돌아옵니다. Android 접근성의 **다시담기 구매 도우미**가 켜져 있어야 합니다.
3. 읽은 상품·옵션·표시 상품가를 확인하고 **상품 정보 적용**을 누릅니다. 금액 한도가 비어 있으면 읽은 상품가를 자동 입력합니다. 기존에 입력한 한도는 유지하며 직접 수정할 수 있습니다.
4. 구매 수량·주기·다음 구매일을 확인하고 **저장**합니다. 기본값은 수량 1개, 30일, 오늘이며 직접 바꿀 수 있습니다. 결제 전 확인 한도는 카드 저장 시 생략할 수 있습니다.

자동 입력은 원화가 명시된 상품가를 하나로 구분할 수 있을 때만 동작합니다. 정가·단가·배송비·적립금·쿠폰/회원 조건 금액은 상품가로 사용하지 않으며, 분리된 가격 라벨·서로 다른 금액·잘린 화면·시간초과 결과는 자동 입력하지 않습니다. 일반 혜택 안내만으로 읽기를 막지는 않습니다. 가격은 안정된 상품명·옵션과 함께 읽고, 읽은 정보를 보완하면서 상품명·옵션을 바꾸면 그 가격을 자동 적용하지 않습니다. 자동 입력 뒤 저장 전에 링크나 상품·옵션을 바꾸면 이전 자동 금액은 비우며, 사용자가 직접 수정한 금액은 유지합니다. 읽지 못한 가격은 직접 입력할 수 있습니다. 표시 상품가는 배송비와 최종 결제 금액을 포함하지 않습니다.

링크는 필수입니다. 링크를 바꾸면 이전 상품명·옵션은 비워 잘못 조합해 저장하지 않도록 합니다. 읽지 못한 정보는 **상품 정보 직접 보완**에서 직접 또는 이미지로 보완할 수 있습니다. PC 이미지가 들어오면 보완 영역이 자동으로 열리며 기존 양식은 유지됩니다. 이미지에 URL이 없으면 링크를 따로 넣어야 합니다.

공개 상품 페이지 요청은 샘플에서 HTTP 403으로 거부되어, 상품 정보는 사용자의 쿠팡 앱 상세 화면에서 읽습니다. 읽은 값은 검토용이며 화면에 없는 정보나 식별 번호를 추측하지 않습니다. 정보 읽기는 상품을 담거나 주문하지 않습니다. 재생성·프로세스 재시작만으로 읽기를 자동 재실행하지 않습니다.

## 상품별 옵션 관리

상품 링크 하나에 선택 옵션 하나를 사용합니다. 카드에는 옵션·다음 구매일·주기·금액 한도와 구매 완료 기록을 한 정보 영역으로 표시합니다. 카드의 옵션 추가·선택 버튼은 제거했습니다. 옵션을 바꾸려면 **더보기(⋯) → 상품 수정**에서 원하는 옵션의 링크를 불러와 저장합니다. 새 링크를 적용하면 해당 링크의 옵션 하나만 사용하며, 기존 상품의 현재 선택값은 그대로 유지합니다.

## 장바구니 담기

카드의 **더보기(⋯) → 장바구니 담기**로 한 상품을, 오른쪽 아래 **상품 등록** 바로 위에 고정된 **예정 상품 담기**로 오늘까지 구매 예정인 활성 상품을 순서대로 담습니다. 묶음 창은 기본으로 **구매 예정**을 선택하며, 미리 담으려면 **전체 활성**을 명시적으로 선택합니다. 비활성·보관 상품은 두 범위에서 모두 제외합니다. 시작 전 날짜·대상 목록을 다시 확인하고, 주소 확인 중 날짜나 등록 정보가 바뀌면 준비를 중단합니다.

- 구매 수량은 **1개**로 유지합니다. 묶음은 최대 20개이며 모든 옵션 주소를 확인한 뒤 명시적으로 시작합니다. 옵션 식별 번호(itemId/vendorItemId)가 모두 있는 주소가 필요합니다.
- 상품명·옵션·담기 버튼 구조가 현재 쿠팡 상세 화면과 일치할 때만 실행합니다. 등록 금액 한도가 있으면 클릭 전에 화면의 **상품가**를 비교합니다. 한도 초과, 화면 읽기 누락, 복수 가격·조건부 가격 등으로 상품가가 불명확하면 담지 않고 중단합니다. 한도가 없으면 가격 검사는 생략합니다.
- 이 비교는 **배송비 포함 최종 결제 금액 검증이 아닙니다.** 취소선·가격 역할을 확정할 수 없는 혼합 금액은 낮은 값을 골라 진행하지 않습니다. 최종 금액은 쿠팡에서 확인해야 합니다.
- 정확한 옵션 주소별로 클릭 전에 앱 담기 기록을 저장합니다. ‘담기 완료 확인’과 ‘요청 결과 확인 필요’ 모두 같은 옵션의 재추가를 막습니다. 앱 재시작·상품 수정·시간 경과로 자동 해제하지 않습니다. 같은 옵션이 포함된 묶음은 첫 상품을 시작하기 전에 중단하며 각 상품 실행 직전에도 재검사합니다.
- 쿠팡에서 직접 담은 상품이나 이 버전 설치 전의 장바구니는 조회하지 못합니다. **앱을 통한 반복 담기 방지**이며 실제 장바구니 조회와 구분합니다. 수동으로 담은 상품이 있으면 수량이 늘어날 수 있습니다.
- 쿠팡에서 삭제·주문한 것을 확인한 뒤 단일 담기 창의 **장바구니 확인 후 기록 해제**를 사용할 수 있습니다. 이 기능은 앱 기록만 지우며 장바구니를 수정하거나 담기를 자동 재시작하지 않습니다. 사용자의 구매 완료 기록이 새로 성공한 경우에도 해당 옵션의 담기 기록을 해제합니다. 해제 저장 실패 시 재추가를 차단합니다.
- 앞 상품의 담기 완료 안내를 확인한 뒤 다음 상품을 시작합니다. 실패·중단·결과 불명 시 나머지를 실행하지 않습니다. 결과를 확인하지 못한 요청은 자동으로 재시도하지 않습니다.
- 주문·결제·구매 완료 기록을 자동 실행하지 않습니다. 지정 시각의 자동 담기와 자동 주문서 이동은 제공하지 않습니다.

실행 결과는 앱으로 돌아와 확인합니다. 필요한 경우 **상세 실행 기록**을 펼칠 수 있습니다. 기존 묶음 실행 기록의 형식 v1은 명시적 v1→v2 마이그레이션으로 한도 필드를 추가하며, 과거에 없던 가격 검사 결과나 담기 기록을 만들어 내지 않습니다. Room 상품 설정과 구매 로그의 현재 스키마는 버전 4입니다.

## 구매 목록과 더보기 메뉴

하단 **구매 목록** 탭의 숫자는 오늘까지 구매 예정인 활성 상품 수입니다. 비활성 상품은 제외하고 다른 탭에서도 확인할 수 있습니다. 카드의 **더보기(⋯)** 메뉴에서 **쿠팡 열기** 또는 **장바구니 담기**를 실행합니다. 구매 완료 기록은 목록에서 바로 사용할 수 있습니다. **예정 상품 담기**와 **상품 등록**은 오른쪽 아래에 위아래로 고정되어 목록을 스크롤해도 사용할 수 있습니다. 담기는 짙은 중립색의 캡슐 버튼, 등록은 밝은 바탕의 테두리 버튼으로 카드의 블루 완료 버튼과 구분합니다. 다크 모드에서는 시스템 테마에 맞는 색상 대비를 사용합니다.

카드의 **활성 / 비활성 스위치**로 상품을 끄거나 다시 켤 수 있습니다. 비활성 상품은 예정 숫자·묶음 담기·알림에서 제외하며 **비활성** 필터로 모아 볼 수 있습니다. 등록 정보와 구매 로그는 유지하고 다시 켜면 기존 예정일을 기준으로 관리합니다. 수동 쿠팡 열기·단일 담기는 계속 사용할 수 있습니다.

목록 상단의 안내 문구와 저장 위치 배지는 제거하고 앱 이름 아래에 필터와 상품을 바로 표시합니다. 카드의 **구매 옵션**과 **다음 구매일**은 큰 글씨로 표시합니다. **구매 완료 기록**은 배경이 있는 버튼이며 기존처럼 확인창을 거쳐 기록합니다. 앱은 밝은 중립 배경·네이비 글자·블루 포인트를 사용하고 시스템 다크 모드도 지원합니다.

주기 설정과 기존 상품 링크를 함께 저장한 참고 샘플은 [testdata/purchase-settings.json](testdata/purchase-settings.json)에 있습니다. 앱은 기기에 등록된 링크로 동작하며 이 JSON을 자동으로 가져오는 기능은 없습니다.

## 상품 삭제와 구매 로그

상품 카드 관리 메뉴의 **상품 삭제 → 삭제**로 등록 정보를 실제 삭제합니다. 기존 **목록에서 보관** 메뉴는 제거했습니다. 삭제하면 구매 목록·예정 상품에서 빠지고 알림과 결제 전 시험 설정도 정리합니다. 삭제 확인을 취소하면 그대로 유지합니다. 삭제는 되돌릴 수 없으며 쿠팡 장바구니를 수정하거나 담기 기록을 초기화하지 않습니다.

**구매 로그**는 상품 관리와 별도 저장소·테이블로 조회하는 읽기 전용 완료 기록입니다. 완료 당시의 상품명·주소·옵션·수량·예정일·완료 시각을 스냅샷으로 남기고 상품을 수정하거나 삭제해도 바꾸지 않습니다. 상품 행이 없어도 로그를 볼 수 있으며 현재 상품을 조회해 과거 값을 채우지 않습니다. 상품 식별자와 회차는 중복 완료 방지용 상관값이며 외래키·연쇄 삭제·현재 상품 조인을 사용하지 않습니다.

로그 화면은 최신 완료순으로 시간·당시 상품명·옵션·수량을 표시하며 수정·재등록 기능은 두지 않습니다. 기존 로그에는 없었던 옵션을 추측해 채우지 않습니다. 구버전에서 이미 보관된 상품은 자동 삭제·재등록하지 않고 기존 비활성 상태를 유지합니다.

## 구매 완료와 알림

쿠팡에서 주문을 확인한 뒤 카드의 **구매 완료 기록**을 누르고 확인합니다. 실제 결제 여부는 사용자가 판단하며 앱은 주문 결과를 조회하지 않습니다. 같은 회차를 여러 번 눌러도 로그와 일정은 한 번만 갱신합니다. 상품을 삭제해도 별도 구매 로그는 유지합니다.

다음 구매일은 **실제 완료한 기기 현지 날짜 + 구매 주기**입니다. 알림은 설정한 시각을 기준으로 WorkManager가 예약합니다. 절전·기기 상태에 따라 늦을 수 있으며 정확한 시각을 보장하지 않습니다. 상품을 비활성화하거나 수정·삭제하면 오래된 알림은 만료됩니다.

## 남겨 둔 결제 전 시험

카드의 관리 메뉴 **⋯ → 결제 전 시험**, 또는 **설정 → 결제 전 시험 설정**에서 엽니다. 등록 조건과 배송비 포함 한도를 확인하고 직접 시작해야 합니다. 상품 화면의 **바로구매**로 주문 화면을 확인하는 시험이며 최종 **결제하기**는 누르지 않습니다.

결제 전 시험은 등록 화면에서 확인해 저장한 옵션 주소를 사용합니다. 옵션 주소를 확인할 수 없으면 상품 수정에서 링크를 다시 불러오도록 안내합니다.

현재 결제 화면의 상품 행·수량·최종 금액 검증은 완성되지 않았습니다. 읽을 수 있는 단계까지만 확인하고 중단할 수 있습니다. 로그인·비밀번호·본인 인증·보안문자는 조작하지 않으며 실제 결제·자동 구매·자동 예약은 활성화할 수 없습니다. 시험으로 구매 로그나 다음 구매일을 바꾸지 않습니다.

## PC 이미지와 클립보드

Windows에서 캡처한 상품 이미지는 `tools`의 콘솔 전송기로 BlueStacks에 보낼 수 있습니다.

```powershell
dotnet publish .\tools
.\tools\dist\RebuyClipboard.exe send --clipboard
.\tools\dist\RebuyClipboard.exe send --image 'C:\captures\product.png'
.\tools\dist\RebuyClipboard.exe sample show
```

Windows용 EXE는 .NET Windows Desktop Runtime 10과 ADB가 필요합니다. 기본 기기는 `127.0.0.1:5555`이며 `--device`·`--adb`로 바꿀 수 있습니다. 요청할 때만 클립보드를 읽으며 자동 감시나 자동 담기는 하지 않습니다. 자세한 명령은 [tools/README.md](tools/README.md), 공통 상품 링크는 [testdata/README.md](testdata/README.md)에 있습니다.

Android 클립보드 이미지와 사진 선택도 **상품 정보 직접 보완**에서 사용할 수 있습니다. 인식 결과를 확인하고 적용해야 양식이 바뀝니다. 한국어 ML Kit 모델을 APK에 포함해 기기에서 읽으며 자체 서버에 이미지를 보내지 않습니다. ML Kit는 성능·사용 통계를 Google에 전송할 수 있습니다. [개인정보 안내](https://developers.google.com/ml-kit/terms)를 참고하세요. PC 전송 이미지는 검토 종료 후 앱 전용 임시 저장소에서 삭제합니다.

## 빌드와 설치

Android 8.0(API 26) 이상을 지원합니다. Android Studio에서 저장소를 열고 JDK 17, Android SDK Platform 35와 Build Tools 35.0.0을 준비합니다. `local.properties`의 `sdk.dir` 또는 `ANDROID_HOME`에 실제 SDK 경로를 지정합니다. 컴퓨터별 설정·SDK·빌드 출력은 Git에 포함하지 않습니다.

```powershell
.\gradlew.bat :app:assembleDebug
adb -s 127.0.0.1:5555 install -r .\app\build\outputs\apk\debug\app-debug.apk
```

디버그 APK는 `app/build/outputs/apk/debug/app-debug.apk`에 생성됩니다. 개발용 서명을 사용합니다. 버전이 다른 DB 형식은 Room의 버전별 Migration(v1→v2→v3→v4)에서만 변환합니다. 일반 저장·조회는 현재 형식만 사용하며 옛 값 자동 복구·병합은 하지 않습니다. 저장할 옵션·한도·선택지는 현재 값을 명시하고, null은 명시적인 비움으로 처리합니다. 현재 스키마는 버전 4입니다. v3→v4는 구매 로그에 nullable 옵션 스냅샷 열만 추가하며 기존 상품과 기록은 유지합니다. 앱을 삭제하면 로컬 데이터도 삭제됩니다.

구성: Kotlin 2.1.20, Jetpack Compose, Room 2.7.1, WorkManager 2.10.1, DataStore 1.1.4. Gradle Wrapper 8.11.1과 Android Gradle Plugin 8.9.2를 사용합니다.

개발 검사는 `app/src/test`와 `app/src/androidTest`에 유지하며 앱의 시험 메뉴와 구분합니다. 접근성 도우미가 실제 동작하는 동안 instrumentation이나 `uiautomator dump`를 실행하면 서비스가 끊길 수 있으므로 실제 연동 확인에는 화면 캡처와 완료 상태를 사용합니다. 실제 확인 범위와 과거 결과는 [VALIDATION.md](VALIDATION.md)에 기록합니다.
